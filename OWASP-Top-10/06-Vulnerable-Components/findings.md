# Findings — OWASP A06: Vulnerable and Outdated Components

## Finding 1: Critical Algorithm-Confusion Vulnerability in `jsonwebtoken` (CVE-2015-9235) — Full Working Exploit

**Severity:** Critical
**Component:** `jsonwebtoken@0.4.0` (npm)
**CVE:** CVE-2015-9235 (CVSS v3.1: 9.8 Critical)
**Status:** Vulnerable — confirmed with a working proof-of-concept

### Description
The application depends on `jsonwebtoken@0.4.0`, a version affected by CVE-2015-9235: the library does not enforce that a token's claimed signing algorithm matches the algorithm actually used to originally sign it. This allows an attacker to take a token originally signed asymmetrically (RS/ES family) and resubmit a forged token claiming a symmetric algorithm (HS*), using the corresponding **public** key as the HMAC secret — a value that, unlike a private key, is often intentionally exposed.

The npm registry itself flags this exact installed version as deprecated, linking directly to the vendor's own vulnerability disclosure.

### Reproduction
1. Confirmed the server signs tokens with `RS256` (extracted from a legitimately issued token's decoded header).
2. Retrieved the RSA **public** verification key from an unauthenticated endpoint (`GET /encryptionkeys/jwt.pub`).
3. Constructed a forged JWT with header `{"alg": "HS256"}` and a payload claiming `role: admin`, `email: admin@juice-sh.op`.
4. Signed the forged token using **HMAC-SHA256 with the public key's raw bytes as the secret**.
5. Submitted the forged token to a genuinely authentication-gated endpoint (`GET /api/Users`), which had already been confirmed to reject unauthenticated requests with a clean `401`.
6. The server accepted the forged token: `200 OK`, returning the complete user table (all accounts, emails, roles, including every admin account).

### Impact
Complete authentication bypass. An attacker with no valid credentials, no password, and no access to any server-side secret can forge a token asserting any identity or role, and have it accepted as genuine by the application. This is not a theoretical citation — it was demonstrated end-to-end against a live, authentication-gated endpoint.

## Finding 2: Authorization Bypass in `express-jwt` (CVE-2020-15084)

**Severity:** High
**Component:** `express-jwt@0.1.3` (npm)
**CVE:** CVE-2020-15084
**Status:** Vulnerable (version-confirmed; not independently re-exploited in this session, as Finding 1 already demonstrates a full bypass through the same authentication layer)

### Description
The declared and lockfile-resolved version of `express-jwt` (`0.1.3`) falls within the affected range (`>=0.1.0 <6.0.0`) for CVE-2020-15084 — a failure to enforce the `algorithms` configuration option, which can permit authorization bypass under certain configurations (particularly in combination with `jwks-rsa`-style key retrieval).

### Impact
Given this middleware sits directly in the authentication path used across the application (as seen in the `401 UnauthorizedError` messages generated by this exact library during testing), an unpatched version here compounds the risk already demonstrated in Finding 1.

## Finding 3: Cross-Site Scripting in `sanitize-html` (CVE-2016-1000237)

**Severity:** Medium
**Component:** `sanitize-html@1.4.2` (npm)
**CVE:** CVE-2016-1000237
**Status:** Vulnerable (version-confirmed; exploitation would require identifying a specific input field that pipes user content through this library — not pursued in this session)

### Description
Versions of `sanitize-html` before `1.4.3` are affected by an XSS vulnerability arising from incorrect HTML tag interpretation during the sanitization process, allowing crafted input to bypass the sanitizer and execute in a victim's browser. The installed version (`1.4.2`) is exactly one patch release below the fix.

### Impact
Any feature relying on this library to sanitize user-supplied HTML/rich text before display is a candidate for stored or reflected XSS. Follow-up work would involve identifying which application features (e.g. product reviews, feedback forms) route through this specific sanitizer.
